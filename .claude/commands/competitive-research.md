# 競合プロダクト調査

対象のペインを解消するようなプロダクト（Web/App）が既に存在するかを調査し、差別化の余地を分析する。

## 入力

$ARGUMENTS に調査対象を指定する。以下のいずれかを受け付ける:

- GitHub Issue 番号（例: `#3`）
- ペインの説明テキスト（例: `会議の議事録を取るのが面倒`）

Issue 番号が指定された場合は以下で内容を取得する:

```bash
gh issue view <番号> --json title,body
```

## 手順

### 1. ペインの整理

対象のペインを以下の観点で整理する:

- 誰の（ターゲットユーザー）
- どんな場面での（コンテキスト）
- どんな課題か（ペインの本質）

### 2. 既存プロダクトの調査

Web 検索で以下を調査する:

- 同じペインを解決しようとしている既存プロダクト（Web サービス、モバイルアプリ、Chrome 拡張など）
- 類似の課題にアプローチしている OSS やツール
- 大手プラットフォームが提供している関連機能

検索キーワード例:
- ペインに関連する英語/日本語キーワード + "app" / "tool" / "service"
- "alternative to" + 関連プロダクト名
- Product Hunt、G2、Capterra などのレビューサイト

### 3. 競合分析

見つかったプロダクトごとに以下を評価する:

| 項目 | 内容 |
|------|------|
| プロダクト名 | 名前と URL |
| 形態 | Web / モバイル / デスクトップ / Chrome 拡張 / CLI |
| 価格帯 | 無料 / Freemium / 有料（月額） |
| ユーザー規模感 | 推定（レビュー数、DL 数などから判断） |
| 強み | 何が優れているか |
| 弱み・不満点 | レビューやフォーラムで見られる不満 |
| ペイン解消度 | 対象のペインをどの程度解消しているか（高/中/低） |

### 4. 差別化分析

以下の観点で差別化の余地を分析する:

| 観点 | 質問 |
|------|------|
| 未解決の隙間 | 既存プロダクトがカバーしきれていない部分はあるか？ |
| UX の改善余地 | 既存プロダクトの UX に対する不満は見つかるか？ |
| 技術的アプローチ | AI / 自動化など、新しい技術で解決できる余地はあるか？ |
| ターゲット特化 | 特定のユーザー層に絞ることで差別化できるか？ |
| 価格戦略 | 無料や低価格で参入できるか？ |
| ローカライズ | 日本市場特有のニーズに対応できるか？ |

### 5. 出力フォーマット

```
## 🔍 競合調査: [ペインの要約]

### ペインの整理

- ターゲット: ...
- コンテキスト: ...
- 課題の本質: ...

### 既存プロダクト一覧

| # | プロダクト名 | 形態 | 価格帯 | ペイン解消度 | URL |
|---|-------------|------|--------|-------------|-----|
| 1 | ... | Web | Freemium | 高 | ... |
| 2 | ... | App | 無料 | 中 | ... |

### 主要競合の詳細

#### 1. [プロダクト名]
- 強み: ...
- 弱み: ...
- ユーザーの声: ...

### 差別化の余地

- ✅ 差別化できそうなポイント（根拠付き）
- ⚠️ 差別化が難しいポイント（理由付き）

### 総合判断

- 競合の密度: 高 / 中 / 低
- 差別化の余地: 大 / 中 / 小
- 参入推奨度: ⭐⭐⭐⭐⭐（5段階）
- 💡 所見: 1-2 文で総合的な見解
```

### 6. Issue へのコメント（任意）

Issue 番号が指定されていた場合、調査結果の要約を Issue コメントとして追加するか確認する。
