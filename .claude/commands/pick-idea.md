# パッと作れそうなアイデアを選定する

GitHub Issue（pain-report ラベル）からペインレポートを取得し、個人開発者が短期間で MVP を作れそうなアイデアを候補として提示する。

## 手順

### 1. GitHub Issue からデータ取得

以下のコマンドで pain-report ラベル付きの open Issue を取得する:

```bash
gh issue list --repo kaionn/pain-collector \
  --label pain-report --state open --limit 100 \
  --json number,title,body,labels,url
```

`📌picked` / `building` ラベルが付いている Issue は既に進行中なので除外する。

### 2. 選定基準

以下の基準で「パッと作れそう」なアイデアを評価する。各項目を 1-5 で採点し、合計点が高い順に並べる。

| 基準 | 説明 | 重み |
|------|------|------|
| ペインの強さ | 深刻度と頻度から需要が見込めるか。「無いと困る」かどうか | x3 |
| スコープの小ささ | MVP を 1-2 日で作れるか。機能を絞れるか | x3 |
| 技術的シンプルさ | 既存の API・ライブラリで実現可能か。複雑なインフラ不要か | x2 |
| 差別化の明確さ | 既存ソリューションとの違いが明確か | x2 |
| 収益可能性 | 課金意欲（high/medium/low/free）と収益モデルが描けるか | x2 |

**最大スコア**: 60/60

> ⚠️ 自己バイアス警告: ジャッジは私（エンジニア）なので、開発者向けプロダクトの「技術的シンプルさ」「スコープの小ささ」を過大評価しがち。逆に一般ユーザー向けプロダクトは「自分で使うイメージが湧かない」だけで低採点しがちなので、意識的にカウンターウェイトをかける。

### 3. フィルタリング

以下に該当するアイテムは除外する:

- `📌picked` / `building` / `📐spec-ready` ラベルが付いているもの（進行中）
- ハードウェア依存や規制が絡むもの（IoT デバイス、医療、金融規制など）
- プラットフォーム依存が強すぎるもの（特定 OS のネイティブアプリ必須など）

### 3.5. ドメイン多様性ルール（重要）

過去の pick が技術寄りに偏らないよう、以下のハード制約を課す:

- **開発者向け候補は最大 1 件まで**: 対象ユーザーが「エンジニア」「DevOps」「開発者」「データサイエンティスト」などの候補は、3-5 件の推薦中で最大 1 件。スコアが高くても 2 件目以降は採用しない
- **一般ユーザー向け候補を最低 2 件含める**: 対象ユーザーが「一般消費者」「主婦」「学生」「高齢者」「特定の属性（アレルギー持ち、子育て中など）」の候補を最低 2 件入れる
- **直近 3 件の pick 履歴と被るドメインは減点**: `gh issue list --label "📌picked" --state all --limit 10` で過去 pick を確認し、同じカテゴリ（お金・家計、テクノロジー、健康・体調、食事・料理 など）が連続する場合は -3 のペナルティ。連続 3 件目以降は除外

### 3.6. ドメイン分類の指針

候補ごとに以下の属性を明示してから評価する:

- **対象ユーザー**: エンジニア / 一般ユーザー / 特定属性（明示）
- **カテゴリ**: pain-report の category ラベル（お金・家計 / 健康・体調 / 仕事・キャリア / 食事・料理 / 移動・通勤 / テクノロジー など）
- **直近 pick との重複**: あり / なし

### 4. 出力フォーマット

候補を 3-5 件、以下のフォーマットで提示する:

```
## 🏆 おすすめ候補

### 1. [アイデア名]
- Issue: #番号
- スコア: XX/60（ペイン x3 / スコープ x3 / 技術 x2 / 差別化 x2 / 収益 x2）
- 対象ユーザー: 一般ユーザー / エンジニア / 特定属性
- カテゴリ: お金・家計 など
- プロダクト形態: CLI / Web / モバイル / Chrome 拡張 など
- 技術スタック案: 具体的なフレームワーク・API
- MVP スコープ: 最小限の機能セット（3 点以内）
- 作れそうな期間: 1日 / 2-3日 / 1週間
- 💡 ひとこと: なぜこれがおすすめか

---
```

候補リストの直後に **ドメイン多様性チェック** を表示する:

```
## ✅ 多様性チェック

- 開発者向け: X件（上限1件）
- 一般ユーザー向け: X件（下限2件）
- 直近 pick との重複カテゴリ: なし / あり（カテゴリ名）
```

### 5. 補足情報

候補提示後、以下も添える:

- 除外したアイデアのうち、惜しかったもの 1-2 件（理由付き）
- スコアは高いが多様性ルールで採用しなかった候補（あれば）
- 選定に迷った場合の判断ポイント
