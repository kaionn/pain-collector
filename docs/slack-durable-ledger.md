# Durable Slack shadow delivery

Normal mode stays `discord` until verified rollout. `NOTIFY_DURABLE_LEDGER=true` in shadow enables metadata-only receipts under `notification-ledger` branch `receipts/v1/<prefix>/<sha256>.json`. The built-in short-lived repository-scoped GITHUB_TOKEN is exposed only as NOTIFY_LEDGER_TOKEN on the existing notification steps, using contents:write for GitHub Contents API compare-and-swap. No new PAT or Slack scopes. Read-only notification workflows now require contents:write; this is necessary only for the ledger.

Stable key uses repository/event/category and the rendered content revision plus optional image hash. Runtime run URL and Discord timestamp decoration are excluded. Logical report dates/weeks/Issue or artifact references belong in the payload; unchanged content means the same event revision. A changed revision gets a separate event. Daily deadlines include dates/days-overdue; weekly reports include their week. Repeated identical failure payloads remain one incident until content changes. Synthetic tests use explicit event revisions.

The winner must durably reserve an event before Slack I/O. Each text timestamp, allocated file ID, file-transfer acknowledgment and upload-completion acknowledgment is persisted before further mutations. A blob-SHA conflict blocks sending. Git/API timeout after a write can leave an unfinished claim; no automatic takeover or expiration is allowed. Failed/unfinished records require independent Slack observation and manual reconciliation, even if the previous process died. This deliberately avoids blind retries and does not promise exactly-once delivery.

Only hashes, channel/message/file IDs, event name, delivery status/stage, originating run/attempt and mode enter the Git branch. Rendered sanitized content and an optional image enter the repository-visible recovery artifact, retained for 90 days or the repository limit. The payload/token/API response/upload URL never enters the Git ledger; token and raw payload do not enter the outbox. If storage is unavailable, Slack is not sent and Discord stays authoritative.

To reconcile, read the record and original run artifact, independently inspect known message/thread/file IDs using the existing Slack connector, then update only confirmed stages through a reviewed recovery workflow using existing runtime secrets. An unknown text/upload outcome must not be replayed wholesale. Do not delete or clear receipts to permit retries. Long-term unresolved outbox items need explicit operator action before artifact expiry.

Rollback shadow by setting NOTIFICATION_MODE=discord; keep the ledger branch and Discord secrets. Do not revert unrelated main changes. Slack-primary code/rollout remains gated on cross-run replay plus real scheduled daily/weekly coverage and notification fallback review.
