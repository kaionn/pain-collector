# Technical Spec: [お金・家計] アプリ内課金の管理ができておらず、二重払いが発生する可能性がある。

_Source: Issue #117_

### 要件定義
- R1. ユーザーとして、サブスクリプションの請求メールを自動的に解析して重複課金を検知したい、なぜなら無駄な支出を避けたいから。
- R2. ユーザーとして、手動でサブスクリプションを登録できるフォームを持ちたい、なぜなら自動検知で漏れた場合に対応したいから。
- R3. ユーザーとして、過去のサブスクリプション履歴を確認したい、なぜなら支出の把握と管理を行いたいから。
- R4. ユーザーとして、サブスクリプションの更新状況を通知してほしい、なぜなら支払いのタイミングを逃したくないから。
- R5. ユーザーとして、サブスクリプションのキャンセルを簡単に行いたい、なぜなら不要なサービスをすぐに止めたいから。

### 技術スタック
- フロントエンド: Next.js 14（App Router）
- バックエンド: Supabase（Auth + Postgres）
- DB: Supabase Postgres
- インフラ/デプロイ: Vercel

### データモデル
| エンティティ         | 主要フィールド                          | リレーション                |
|----------------------|----------------------------------------|-----------------------------|
| User                 | id, email, password                    | -                           |
| Subscription         | id, user_id, name, amount, status     | User (1対多)               |
| BillingEmail         | id, subscription_id, email_content     | Subscription (1対1)         |
| Notification         | id, user_id, subscription_id, message  | User (1対多), Subscription (1対多) |

### API エンドポイント
| メソッド | パス                          | 説明                                 |
|----------|-------------------------------|--------------------------------------|
| POST     | /api/auth/signup              | 新規ユーザー登録                     |
| POST     | /api/auth/login               | ユーザーログイン                     |
| GET      | /api/subscriptions             | ユーザーのサブスクリプション一覧取得 |
| POST     | /api/subscriptions             | 新しいサブスクリプションを追加      |
| DELETE   | /api/subscriptions/{id}       | サブスクリプションを削除            |
| POST     | /api/billing/emails           | 請求メールを解析しサブスクリプションを登録 |
| GET      | /api/notifications             | ユーザーの通知一覧取得              |
