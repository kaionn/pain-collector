# Technical Spec: [お金・家計] アプリ内課金の管理ができておらず、二重払いが発生する可能性がある。

_Source: Issue #117_

### 要件定義
- R1. ユーザーとして、アプリ内課金の履歴を確認したい、なぜなら二重払いを防ぎたいから。
- R2. ユーザーとして、課金のリマインダーを受け取りたい、なぜなら支払いを忘れたくないから。
- R3. ユーザーとして、過去の支払い履歴をエクスポートしたい、なぜなら家計の見直しを行いたいから。
- R4. ユーザーとして、課金内容を簡単に管理したい、なぜなら手間を減らしたいから。
- R5. ユーザーとして、課金の通知を受け取りたい、なぜなら支出を把握したいから。

### 技術スタック
- フロントエンド: React Native
- バックエンド: Node.js + Express
- DB: MongoDB
- インフラ/デプロイ: AWS (EC2, S3, RDS)

### データモデル
| エンティティ | 主要フィールド | リレーション |
|--------------|----------------|--------------|
| User         | userId, name, email | 1対多 (User - Subscription) |
| Subscription | subscriptionId, userId, amount, status, nextPaymentDate | 多対1 (Subscription - User) |

### API エンドポイント
| メソッド | パス                     | 説明                         |
|----------|-------------------------|------------------------------|
| GET      | /api/users              | ユーザー情報の取得          |
| POST     | /api/users              | ユーザーの新規登録          |
| GET      | /api/subscriptions       | ユーザーの課金情報の取得    |
| POST     | /api/subscriptions       | 新規課金情報の登録          |
| PUT      | /api/subscriptions/:id   | 課金情報の更新              |
| DELETE   | /api/subscriptions/:id   | 課金情報の削除              |

### 画面一覧
| パス               | 画面名               | 主要コンポーネント          |
|-------------------|---------------------|-----------------------------|
| /home             | ホーム画面         | 課金履歴リスト、通知設定    |
| /subscriptions     | 課金管理画面       | 課金情報リスト、追加ボタン  |
| /settings          | 設定画面           | ユーザー情報、リマインダー設定 |
